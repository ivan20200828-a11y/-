# Сделка онлайн

Приложение для удалённых сделок: клиент проходит проверку личности, подписывает договор кодом из SMS, платит первоначальный взнос и дальше видит договор и график платежей в личном кабинете. Менеджер создаёт сделки и видит, на каком этапе каждый клиент.

Одна кодовая база для iPhone, Android и браузера (Expo SDK 57, React Native, Expo Router).

## Что уже работает

Клиент: приглашение → подтверждение телефона по SMS → фото паспорта и селфи, автозаполнение данных → договор с графиком → подпись простой электронной подписью → оплата взноса (СБП или карта) → личный кабинет (график, договор, история платежей, оплата следующего платежа).

Менеджер: список сделок со статусами, поиском и фильтрами, сводка по деньгам (получено, за месяц, ожидается за 30 дней, просрочено), выгрузка платежей и сделок в таблицы для Excel, создание сделки (сумма, взнос, срок), карточка сделки с договором, графиком и фото документов, отмена сделки. Администратор добавляет сотрудников и заполняет реквизиты компании.

## Сервер

Папка `server/`: Node.js 22.18+, Fastify, база SQLite (встроенная в Node). Сервер хранит сделки, платежи и журнал всех действий клиента (кто, когда подтвердил телефон, подписал договор, оплатил), проверяет порядок этапов и ограничивает число попыток ввода кода.

```bash
cd server
npm install
npm start         # http://localhost:3000, при первом запуске создаёт демо-сделки
npm test          # автотесты всего пути сделки
```

Настройки через переменные окружения: `PORT`, `DB_FILE` (файл базы, по умолчанию `sdelka.db`), `SEED=off` (без демо-сделок), `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ADMIN_NAME` (первый менеджер, создаётся при первом запуске; по умолчанию `manager@demo.ru` / `demo1234`), `APP_URL` (адрес веб-приложения для ссылок в SMS), `WEB_DIR` (папка с веб-сборкой, если сервер должен отдавать и приложение).

Менеджеры входят по почте и паролю. Первый менеджер — администратор: он добавляет сотрудников в разделе «Сотрудники». В сделке менеджер копирует ссылку для клиента или отправляет SMS повторно, смотрит фото паспорта и селфи из проверки и может отменить неоплаченную сделку с указанием причины; в истории видно, кто из сотрудников что сделал. Список сделок ищется по ФИО, телефону, номеру и предмету и фильтруется по этапам.

Пароли хранятся в виде хеша scrypt, после 5 неверных попыток вход блокируется на 15 минут). Договор скачивается в PDF: `/api/client/<код приглашения>/contract.pdf`, после подписания в нём указаны подписант, время и идентификатор подписи.

### Оплата через Т-Кассу

По умолчанию оплата тестовая и проходит сразу. Чтобы принимать деньги через интернет-эквайринг Т-Банка (СБП и карты), задайте:

- `PAYMENTS_PROVIDER=tkassa`
- `TKASSA_TERMINAL_KEY` и `TKASSA_PASSWORD` — ключ и пароль терминала из личного кабинета Т-Кассы (для проверки сначала тестовый терминал)
- `PUBLIC_URL` — внешний адрес сервера; банк присылает подтверждения оплаты на `PUBLIC_URL/api/payments/notify`
- `APP_URL` — адрес веб-приложения, куда банк вернёт клиента после оплаты
- `TKASSA_API_URL` — только если банк выдал другой адрес API (по умолчанию `https://securepay.tinkoff.ru/v2`)

Как это работает: клиент нажимает «Оплатить», сервер создаёт платёж в банке. При оплате по СБП открывается приложение банка клиента (на компьютере QR-код), картой — защищённая страница банка. Экран ждёт подтверждения; платёж засчитывается только после уведомления банка с верной подписью и совпадающей суммой. Если уведомление задерживается, сервер сам спрашивает у банка статус. Повторная оплата того же платежа не засчитывается дважды и отмечается в журнале сделки для возврата. Подключение сверено с открытыми библиотеками для Т-Кассы (подпись запросов, ссылка СБП, ответ на уведомления); перед запуском его нужно проверить на тестовом терминале банка. Чеки по 54-ФЗ пока не передаются: их добавим вместе с выбором онлайн-кассы.

Другой банк подключается отдельным файлом в `server/src/payments/` с тем же набором функций.

### Соглашение о простой электронной подписи

Перед подписанием клиент принимает соглашение об использовании простой электронной подписи (63-ФЗ, ст. 9). Текст лежит в `server/src/esign.ts`, принятая редакция и время сохраняются в сделке и печатаются в договоре, сам текст идёт в PDF приложением № 2. Текст — черновик, его нужно согласовать с юристом; при изменении текста увеличьте номер редакции.

### Напоминания о платежах

Сервер раз в час проверяет активные сделки и отправляет клиенту SMS за 3 дня до платежа и после пропущенной даты, каждое напоминание один раз (видно в истории сделки). Клиент и менеджер видят просрочку в кабинете; сделки с просрочкой стоят в списке первыми.

### Реквизиты компании

Администратор заполняет реквизиты в разделе «Компания» (название, ИНН, КПП, ОГРН, адрес, подписант, банк, контакты). Они печатаются в преамбуле и в разделе «Реквизиты сторон» каждого нового договора. Сделка запоминает реквизиты на момент создания, поэтому смена реквизитов не меняет уже созданные договоры. Пока реквизиты не заполнены, в списке сделок висит напоминание.

### SMS через SMSC.ru

С `SMS_PROVIDER=smsc`, `SMSC_LOGIN`, `SMSC_PASSWORD` (и при желании `SMSC_SENDER`) коды, приглашения и напоминания уходят настоящими SMS, коды становятся случайными. Если SMS не ушло, клиент видит понятную ошибку, а в истории сделки появляется запись; напоминание повторится в следующий час. Баннер тестового режима в приложении показывает только то, что ещё имитируется (`GET /api/health` → `test`).

### Чеки по 54-ФЗ

Если задан `TKASSA_TAXATION`, к каждому платежу через Т-Кассу прикладывается чек (`Receipt` в `Init`) с телефоном клиента. Товар передаётся при подписании (`TKASSA_HANDOVER=signing`, по умолчанию): взнос — «частичный расчёт и кредит», платежи — «оплата кредита». Товар после полной оплаты (`full_payment`): платежи — «частичная предоплата», последний — «полный расчёт». НДС — `TKASSA_TAX` (по умолчанию `none`), формат ФФД — `TKASSA_FFD` (`1.2` по умолчанию). Признаки расчёта должен подтвердить бухгалтер. Платежи переводом и наличными чеками через Т-Кассу не пробиваются.

### Резервные копии

Сервер раз в день делает копию базы (`VACUUM INTO`) в папку `backups` рядом с базой (`BACKUP_DIR`, `off` выключает) и хранит последние `BACKUP_KEEP` (14). Администратор скачивает свежую копию кнопкой «Скачать копию базы» в разделе «Компания».

### Сотрудники и безопасность

Каждый менеджер меняет свой пароль в «Сменить пароль»; остальные его входы при этом закрываются. Администратор в «Сотрудники» задаёт коллеге новый пароль или отключает доступ (например, при увольнении); сделки остаются, отключить себя или последнего администратора нельзя.

Сервер ограничивает попытки входа (20 за 10 минут с одного адреса) и запросы клиента (120 в минуту), SMS с кодом — не чаще раза в 30 секунд и не больше 5 в час на сделку, повторные приглашения — 3 в час. Ответы идут с заголовками `Referrer-Policy: no-referrer` (ссылка клиента содержит ключ сделки), `X-Frame-Options`, `nosniff`, по HTTPS — `Strict-Transport-Security`. За Caddy задайте `TRUST_PROXY=1`, чтобы ограничения считались по настоящему адресу клиента.

### Оплата вне приложения и досрочное погашение

Клиент может оплатить взнос или очередной платёж переводом по реквизитам компании: приложение показывает реквизиты, сумму и назначение платежа. Когда деньги пришли на счёт или приняты наличными, менеджер нажимает «Отметить оплату вне приложения» в карточке сделки (`POST /api/deals/:id/payments`, способ `transfer` или `cash`, с комментарием, например номером платёжного поручения). Клиент сразу видит платёж в кабинете.

Клиент может погасить весь остаток досрочно одним платежом, по СБП или переводом. Досрочное погашение записывается отдельной строкой на каждый закрытый платёж графика с общим номером операции.

### Выгрузка в Excel

Кнопки «Выгрузить платежи» и «Выгрузить сделки» скачивают CSV (UTF-8, разделитель «;»), который Excel открывает без настройки. Ссылка на файл одноразовая и действует 5 минут: `POST /api/export/key`, затем `GET /api/export/payments.csv?key=…` или `deals.csv`.

## Готовый пакет

`scripts/build-release.sh` собирает `release/sdelka-online.zip`: сервер с зависимостями, собранную веб-версию, скрипты запуска `start.bat`, `start.command`, `start.sh`, файл настроек `settings.env` и инструкцию `ИНСТРУКЦИЯ.html`. На компьютере нужен только Node.js 22.18 или новее. Для сервера в пакете есть `docker-compose.yml` с автоматическим HTTPS (Caddy): `docker compose --env-file settings.env up -d`. Шаблоны этих файлов лежат в `release-kit/`.

Веб-версию можно добавить на экран телефона как приложение (manifest и иконки в `public/`). Сборки для App Store и Google Play настроены в `eas.json`: перед сборкой впишите адрес своего сервера в `EXPO_PUBLIC_API_URL`.

## Запуск на сервере

Сервер и веб-версия приложения запускаются одним контейнером: приложение открывается по адресу сервера, API работает на нём же.

```bash
echo "ADMIN_EMAIL=you@company.ru" > .env
echo "ADMIN_PASSWORD=надёжный-пароль" >> .env
docker compose up -d --build     # приложение на порту 3000
```

База хранится в томе `data`. Демо-сделки в контейнере по умолчанию выключены (`SEED=off`); чтобы показать приложение на примерах, запустите с `SEED=on`. Для работы с клиентами нужен HTTPS: поставьте перед контейнером веб-сервер с сертификатом (например, Caddy или Nginx) и сервер в России (152-ФЗ).

## Приложение

```bash
npm install
npm run web       # в браузере, сервер должен быть запущен
npm start         # QR-код для приложения Expo Go на телефоне
```

Адрес сервера задаётся `EXPO_PUBLIC_API_URL` (по умолчанию `http://localhost:3000`, пустое значение — тот же адрес, с которого открыто веб-приложение; телефону нужен адрес компьютера в сети, например `http://192.168.1.10:3000`). Клиент открывает свою сделку по ссылке `/client?t=<код приглашения>`; без кода открывается демо-сделка.

## Тестовый режим

Внешние сервисы имитируются в `server/src/providers.ts`: SMS не отправляются (код везде `1234`), деньги не списываются (если не включена Т-Касса), паспорт не распознаётся по-настоящему (подставляется пример).

Что осталось до работы с реальными клиентами:
1. SMS-шлюз для кодов.
2. Сервис распознавания паспорта и сверки лица (KYC).
3. Договор с банком на эквайринг и ключи терминала (подключение к Т-Кассе уже готово), онлайн-касса для чеков.
4. Оператор электронной подписи, если простой подписи по SMS недостаточно; договор в PDF.
5. Размещение сервера (хостинг с хранением данных в России по 152-ФЗ).

Сборка для App Store и Google Play: `npx eas-cli@latest build` (нужен аккаунт Expo, Apple Developer и Google Play Console).

## Структура

- `src/app/` — экраны (каждый файл — отдельный экран): `client/*` для клиента, `manager/*` для менеджера
- `src/api.ts` — обращения к серверу
- `src/state/` — модель сделки и загрузка данных
- `server/` — сервер: `src/deals.ts` правила сделки, `src/app.ts` адреса API, `src/providers.ts` внешние сервисы
- `src/lib/` — расчёт графика платежей, форматирование сумм и дат
- `src/ui/` — общие компоненты, договор и таблица графика
